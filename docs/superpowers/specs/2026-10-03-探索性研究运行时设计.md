# 探索性研究运行时设计

## 目标与成功定义

本设计将 Long Horizon Runtime 从“执行预先分解的任务图”扩展为“在证据约束下持续推进探索”的运行时。它面向 RAG 方案选择、历史密码分析、实验设计等问题：终点清楚，但到达终点的正确路径未知，且失败实验本身会改变下一步。

成功不是模型声称找到了答案，而是在冻结的问题范围内满足下列任一条件：

1. 产生由独立验证器和复审通过的有效改进或可复现机制；
2. 完成预先定义的搜索范围，并给出每一排除结论的可复现证据；
3. 记录无法靠运行时自主消除的真实外部阻塞，并暂停等待输入。

阴性实验不是终点。只要仍有预算、存在未排除且可验证的假设，运行时必须将阴性结果写入研究账本，并自动选择下一项可检验假设。

## 范围与非目标

本期新增“探索研究任务”这一计划形态；普通确定性任务继续使用当前的计划修订、验收契约、重试和安全策略。

不承诺全局最优、数学真理或对未知问题的必然破解；所有“当前最佳”均限定在冻结的数据、工具、预算、指标、已探索空间和证据等级内。本期不授权未登记的外部写入、任意命令、任意网络访问或由模型自行扩大研究范围。

## 核心模型

探索任务由不可变的 `ResearchContract` 创建，取代一次性完整 DAG 作为根约束：

```text
ResearchContract
├─ objective：问题与目标函数
├─ scope：允许资料、冻结日期、禁止资料、数据指纹
├─ constraints：预算、并发、工具、外部副作用边界
├─ evidencePolicy：证据等级、独立复现与人工升级要求
├─ searchBoundary：允许的假设族、机制复杂度上限、停止准则
└─ successCriteria：有效改进、范围穷尽、真实阻塞的判定方式
```

每个研究批次只计划下一小段可执行工作，而非声称知道完整路线。批次最多包含有限数量、具备明确输入和产物的节点；节点必须额外声明：待检验假设、可区分的竞争解释、预期信息价值、成本上限、反证条件、验收检查和产物类型。

运行时新增四类追加事件与投影：

- `HypothesisRegistered`、`HypothesisUpdated`、`HypothesisRetired`：记录假设、依赖、先验理由和状态；
- `ExperimentRegistered`、`ExperimentCompleted`：固定输入、程序/提示版本、随机种子、预算、产物与结果；
- `EvidenceAssessed`：将证据标记为支持、反驳、不充分或矛盾，并链接验收 bundle；
- `ResearchDecisionRecorded`：记录候选下一步、评分、选择、排除理由、适用范围与研究轮次。

以上记录与现有事件日志同样追加写、可按修订重建；不得用后一次结论覆盖早期失败或已淘汰假设。

## 研究闭环

```text
研究契约与初始问题包
  -> 假设生成与去重
  -> 小批次实验计划
  -> 执行者产生候选产物
  -> 宿主验收器固定证据 bundle
  -> 独立复审与反例搜索
  -> 研究决策：采纳、淘汰、复现、转向或暂停
  -> 下一研究批次
```

规划器只提出候选批次，不能宣布结论成立。执行 Agent 只写入任务工作区和候选工件；验收沿用现有宿主控制的 `acceptanceChecks`。复审 Agent 必须是独立会话，读取冻结的工件与量规，不读取执行 Agent 的私有推理。若复审与确定性检查矛盾，记录矛盾证据并优先安排能区分二者的复现实验。

每轮结束后，研究协调器在未淘汰的假设中选择下一步。它使用现有目标条件因果优势思想，但输出仅是受限决策分数：

```text
score = 预期信息价值 + 预期目标改善
        - 执行成本 - 不可逆风险 - 约束风险
```

分数必须附带证据和不确定性，不能被写成“全局最优”断言。若最高分候选需要外部副作用、扩大 `ResearchContract` 的范围、使已验证产物失效或无法界定影响子图，则像现有重规划一样停在等待确认状态。

## 证据等级与结论门槛

研究结论从低到高分为：`候选`、`已复现`、`已交叉验证`、`已接受`。至少一项宿主确定性检查通过才能从候选进入已复现；第二个独立实现或不同模型/随机种子的复跑才能进入已交叉验证；需要领域解释、外部档案或真实性判断的结论只能由指定人工或受信任外部复审升为已接受。

每个“失败”必须保存：输入版本、操作版本、执行参数、验收输出、失败分类、受影响假设和下一步推荐。基础设施失败不构成反证；内容性失败才会降低相应假设的优先级。搜索空间耗尽时，报告“在范围内未找到”，而非“问题无解”。

## 标志性真实验收

验收不以通用评测集取代真实研究，而采用两个版本化问题包。

### 拿破仑信件回归包

使用已公开的 Marmont 密码材料及其可复现解法，要求从扫描件到符号账本、映射搜索、文本评分、去历史语料复跑和独立验证的完整证据链。明文匹配不足以通过；运行时必须展示中断恢复、阴性假设留档和工件可重放。这验证持续研究基础设施是否有效。

### Kryptos K4 机制重建包

任务是从公开密文、公开提示和冻结资料中重建简洁、可逆的候选加密机制，而不是直接复述已经泄露的明文。问题包明确禁止泄露明文、非公开档案与后验解答，并固定允许的密码原语、复杂度上限与材料版本。候选机制必须以独立实现逐字符生成公开密文；若无法完成，运行时需产出可复现的机制排除报告与下一研究方向。

此题的“原作者机制”在公开条件下未必有可得的真值，因此只能将逐字符生成、模型复杂度、独立复现和外部专家复审作为可证伪的阶段门槛，不能在无作者确认时宣称已得到唯一原解。

## 接口、展示与安全

新增只使用命名输入对象的 UI/API 操作：创建研究任务、读取研究账本、提交复审、确认需扩大范围的研究决定、导出脱敏证据包。Cockpit 新增“研究轮次”视图：显示当前问题范围、预算、活跃假设、被排除路线、证据等级、下一步理由和停止条件；任务 DAG 仍显示当前批次，但不得伪装成完整研究路线。

研究包的资料清单通过哈希固定。网页检索、命令、数据库与外部服务继续经过部署拥有的注册表和验收框架；记录脱敏后的出处、时间与内容哈希。子 Agent 沿用 `long_task_*` 生命周期工具和原生目标工具的拒绝列表，不能自行创建、归档、确认或扩展研究任务。

## 迁移与交付顺序

1. 定义 `ResearchContract`、研究账本事件/投影和只读 DTO；不改变普通任务语义。
2. 让规划器生成并验证研究批次，接入现有验收 bundle 与失败后重规划。
3. 实现独立复审、证据等级和“阴性结果必须推进”的选择策略。
4. 实现 Cockpit 研究视图、可复现实验导出和冻结问题包加载器。
5. 先以拿破仑回归包验证持久化、恢复、复现和阴性转向；再受控启动 K4 机制重建包。

每一步先写失败测试，且不得修改用户 profile 配置或放宽当前子 Agent 权限边界。

## 验收标准

- 重启后可从事件与工件精确重建研究账本、当前批次和所有已淘汰假设。
- 阴性内容实验必须产生下一项有界、可验证的候选；若没有候选，必须提供搜索空间耗尽证据或明确外部阻塞。
- 没有通过宿主验收和独立复审的候选不能显示为研究结论。
- 任何自动批次变更都不得扩大问题包范围、触及外部副作用或使已验证工件失效。
- 拿破仑回归包可从冻结输入独立重放并产生同一证据结论；K4 包的每个候选机制都能由独立实现逐字符验证或被明确否证。
