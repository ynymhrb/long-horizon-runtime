# 长任务故障注入评测设计

日期：2026-09-17

## 目标与边界

为 Long Horizon Runtime 建立可重复、可审计的双层评测体系：确定性层用于持续集成回归，真实模型层用于本机已安装模型的发布前验收。评测验证任务在故障后的恢复能力、幂等性和最终正确性，而不将模型的自然语言自述当作正确性证据。

评测只允许在唯一临时工作区执行 `read_only` 任务。禁止网络、用户配置写入、第三方系统写入和 `external_effect`。任何发现的外部副作用立即硬停止并保留证据。

本设计不修改 DeepSeek Harness，不改变用户 profile 配置，也不把评测故障注入暴露为普通用户任务能力。

## 套件结构

### 确定性层

保留现有 35 个版本化场景作为 CI 套件，并为故障位置、恢复和幂等性补充可执行断言。它使用 fixture planner/executor，要求快速、无模型成本、字节稳定的结果。

### 真实模型层

新增固定的 30 个任务，由本机安装且可被 DSH 调用的模型执行。每个任务记录精确模型标识、可用版本信息、采样参数、提示词哈希、工具集合哈希、token 预算和 wall-time 预算。模型或输入环境变化产生新的基线，不与旧结果混合聚合。

任务分为六类故障，每类五个变体：

| 故障 | 注入点 | 变体维度 |
| --- | --- | --- |
| 第 5 步 crash | 第五个已审计步骤提交后 | DAG 深度、已验证产物、恢复前后 child 身份 |
| 第 10 步 context reset | 第十个步骤后替换 child 会话 | durable snapshot 完整度、依赖上下文、后续任务数 |
| command timeout | 指定受控命令超时 | 超时前是否产生有效产物、重试预算 |
| 测试失败 | 独立 oracle 返回失败 | 局部修复可行性、是否触发安全重规划 |
| 文件已创建但状态未更新 | 产物提交与投影更新之间 | 重启恢复、重复写入检测、校验状态 |
| 重规划后重复任务 | 候选计划含相同逻辑动作 | 相同任务键、不同任务 ID、下游依赖 |

每类包含一个正常对照或配对对照。对照与故障变体的任务目标和代码 oracle 相同，仅故障计划不同。

## 评测专用执行适配层

故障注入与观测位于插件现有 planner/execution provider 边界的评测适配层。适配层只由显式真实评测命令启用，并要求：临时工作区、只读计划、评测 run ID 和循环回调的本地证据目录。

它维护每个逻辑步骤的稳定步骤键、尝试 ID、输入/输出摘要哈希、开始结束时间、会话标识和故障决定。第 5 步 crash 与第 10 步 context reset 都在已持久化步骤边界发生：前者中断当前 child；后者关闭其上下文并从 durable snapshot 启动新 child。两者不得伪造成功或覆盖历史事件。

受控 command timeout 只杀死临时工作区内的命令树。测试失败由版本化的独立 oracle 产生。文件已创建但状态未更新使用带幂等键的临时产物模拟原子性缺口；重规划重复任务通过逻辑动作键检测，而非依赖任务 ID 的偶然不同。

## 证据与指标

每个确定性或真实运行输出不可变 evidence bundle。现有运行、命令、任务、事件、快照、产物、断言和环境文件继续保留；真实层另增加：

- `model.json`：模型、采样、预算与输入环境指纹；
- `steps.json`：步骤 trace、稳定逻辑动作键和故障注入记录；
- `tokens.json`：按 planner、child、恢复尝试汇总的输入、输出与总 token；
- `interventions.json`：显式人工控制事件；
- `correctness.json`：独立代码/任务 oracle 的结果。

所有缺失的必需证据都使运行变为 `inconclusive`，并在报告中单独计数；禁止以零值补齐。

| 指标 | 定义 |
| --- | --- |
| Task Success Rate | 最终通过任务专属正确性 oracle 的任务数 / 有完整证据的任务数 |
| Recovery Success Rate | 发生注入故障且未重新创建目标、最终通过正确性 oracle 的任务数 / 有完整故障证据的任务数 |
| 重复副作用次数 | 受控逻辑提交总次数 - 唯一幂等键数，最小值为零 |
| 人工介入次数 | 暂停、恢复、确认、拒绝、手工重试或目标编辑等显式控制事件总数 |
| 平均重试次数 | 所有终止任务的 `(attempt 数 - 1)` 平均值 |
| token 增长 | 与同一任务正常对照相比的输入、输出和总 token 差；缺少可比对照时为 `null` |
| 最终代码正确率 | 通过独立代码/任务 oracle 的代码型任务数 / 有完整证据的代码型任务数 |

Task Success Rate 与最终代码正确率刻意分开：前者适用于所有任务，后者只适用于包含代码 oracle 的任务。重复副作用只统计临时工作区内带幂等键的受控提交，不制造真实外部写入。

## 报告与门禁

评测生成机器可读 `live-suite-report.json` 与中文摘要。聚合按 suite、模型环境指纹、场景版本和运行时间分区，禁止跨环境直接平均。

CI 仅执行确定性层。真实模型层由显式命令启动，不在安装、激活或普通测试期间运行。真实层门禁要求：30 个任务均有完整证据；没有外部副作用；重复逻辑副作用为零；每项正确性 oracle 都有明确 pass/fail。报告必须列出未运行与 inconclusive 任务，不得将它们计为成功。

## 测试策略

新增行为先写 focused Vitest 失败测试，再实现最小功能。测试覆盖：注入点准确性、重启/换会话后的持久状态、命令树 timeout、产物幂等键、重复重规划检测、token 缺失处理、指标分母以及报告稳定排序。

真实层自身不作为单元测试前提；其配置和证据 contract 使用确定性 fixture 验证。发布前再使用本机模型运行一次 30 任务基线，并保留不可变 evidence bundle。
