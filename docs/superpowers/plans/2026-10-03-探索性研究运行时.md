# 探索性研究运行时实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 为 Long Horizon Runtime 增加可审计的探索研究闭环，使其在阴性结果后基于证据继续提出并验证有界假设。

**架构：** 新增不可变研究契约、追加式研究账本和问题包加载器；现有任务 DAG 仅表示一个研究批次。运行时在宿主验收完成后登记证据、调用独立复审、由有界评分策略选择下一批或安全暂停；浏览器通过既有 `longTasks` 远程接口读取研究状态。

**技术栈：** TypeScript、Node SQLite、Vitest、Cordis/Typert、React 18、现有验收契约与 ArtifactStore。

**规格：** `docs/superpowers/specs/2026-10-03-探索性研究运行时设计.md`

## 全局约束

- 仅修改 `D:\code\long-horizon-runtime`；不得修改 DeepSeek Harness 源码或用户 profile 配置。
- 所有研究状态、证据、失败和决策均追加写且可重建；不得以后来的结论覆盖先前记录。
- 自动研究批次不得扩大 `ResearchContract` 范围、触及外部副作用、使已验证工件失效或绕过现有子 Agent 工具拒绝列表。
- 阴性内容实验必须留下可复现证据并选择下一项有界假设；只有范围穷尽或真实外部阻塞才可停止。
- 结论必须区分候选、已复现、已交叉验证、已接受；独立 LLM 复审不能替代宿主确定性验收。
- 所有浏览器远程方法使用一个命名输入对象；所有新建或修改文档使用中文。
- 每项行为变化先写聚焦的失败 Vitest 测试；每项任务结束后运行其列出的测试并提交。

## 评审重点

- 禁止资料或数据哈希不匹配的问题包必须在规划前拒绝；在任务 1 的契约解析测试覆盖。
- 重启后的账本重建不得丢失已淘汰假设、实验参数或证据等级；在任务 2 的 SQLite 重建测试覆盖。
- 基础设施失败和被用户中断的尝试不得被写为反证或触发下一假设；在任务 3 的运行时测试覆盖。
- 最高评分候选如扩大范围、需要外部副作用或无法给出有界影响，必须等待确认；在任务 3 的策略测试覆盖。
- 候选机制即使文本看似合理，只要独立实现未逐字符验证，就不得显示为已复现；在任务 4 的问题包与 API 测试覆盖。

## 文件结构

- `src/research-contract.ts`：解析、验证和规范化 `ResearchContract` 与问题包元数据。
- `src/research-ledger.ts`：研究假设、实验、证据与研究决定的 JSON 安全 DTO 和投影读取。
- `src/research-policy.ts`：对可执行下一假设排序，返回自动应用或等待确认的有界决策。
- `src/research-packages.ts`：冻结资料清单、验收器引用和拿破仑/K4 问题包定义与加载验证。
- `src/domain.ts`、`src/event-store.ts`、`src/projections.ts`：研究任务字段、事件、SQLite 投影与重建。
- `src/adapters.ts`、`src/runtime.ts`、`src/scheduler.ts`：批次规划输入、验收后登记、独立复审与下一轮调度。
- `src/task-ui-api.ts`、`src/remote.ts`、`client/*`：研究账本 DTO、远程读取和 Cockpit 研究轮次展示。
- `tests/research-*.spec.ts`：契约、账本、策略、运行时和问题包的聚焦覆盖。
