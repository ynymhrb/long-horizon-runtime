# 任务运行统计 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**目标：** 为长期任务提供可审计、重启后可恢复的运行轮数、累计活跃执行时长和自然经过时长，并在任务界面展示。

**架构：** 调度外层在真正派发节点前后记录轮次事件；事件存储以事件时间与轮次编号推导统计，运行时仅在读取时补齐开放轮次；远端 DTO 将统计传给任务列表、任务条与驾驶舱。

**技术栈：** TypeScript、Vitest、Node SQLite、React 18。

**设计依据：** `docs/superpowers/specs/2026-10-29-任务运行统计设计.md`

## 文件结构

- `src/domain.ts`：定义运行统计与轮次投影类型。
- `src/event-store.ts`、`src/projections.ts`：投影并读取持久轮次事件和统计。
- `src/runtime.ts`、`src/scheduler.ts`：围绕实际调度写入轮次边界，并向 `GoalView` 暴露动态统计。
- `src/task-ui.ts`、`src/task-ui-api.ts`：将统计纳入安全的浏览器 DTO。
- `client/task-presentation.js`、`client/TaskArea.js`、`client/TaskStrip.js`、`client/TaskCockpit.js`：格式化并显示统计。
- `tests/event-store.spec.ts`、`tests/runtime.spec.ts`、`tests/task-ui.spec.ts`、`tests/task-cockpit.spec.ts`：回归测试。

## 任务 1：持久轮次与统计投影

**文件：** `src/domain.ts`、`src/event-store.ts`、`src/projections.ts`、`tests/event-store.spec.ts`

1. 编写失败测试：开始并结束两轮后，事件存储返回正确轮次、活跃时长和自然经过时长；开放轮次以传入“当前时刻”补齐；时钟回拨截为零。
2. 运行 `pnpm vitest run tests/event-store.spec.ts -t "运行轮次|运行统计"`，确认测试因 API 不存在而失败。
3. 添加 `RunRoundProjection` 与 `RuntimeMetrics`，投影 `GoalRunRoundStarted`/`GoalRunRoundFinished`；提供按任务读取统计的方法。
4. 重跑聚焦测试并确认通过。
5. 提交：`feat: persist task runtime metrics`。

## 任务 2：调度生命周期边界

**文件：** `src/runtime.ts`、`src/scheduler.ts`、`tests/runtime.spec.ts`

1. 编写失败测试：真实派发产生一轮；同轮并发及重试不增轮；暂停、取消、自动重规划、会话停止关闭开放轮；恢复并重新派发创建下一轮。
2. 运行 `pnpm vitest run tests/runtime.spec.ts -t "运行轮次|运行时长"`，确认缺少轮次事件或指标。
3. 在运行时的调度边界包装实际 `runRound`：仅当该轮准备派发节点时开始；在所有状态出口最终关闭；保留启动修订；不改动节点重试逻辑。
4. 将存储统计加入 `GoalView`，使用注入的 `now` 保证测试和开放轮次计算可控。
5. 重跑聚焦测试并确认通过。
6. 提交：`feat: record task runtime rounds`。

## 任务 3：远端 DTO 与界面展示

**文件：** `src/task-ui.ts`、`src/task-ui-api.ts`、`client/task-presentation.js`、`client/TaskArea.js`、`client/TaskStrip.js`、`client/TaskCockpit.js`、`tests/task-ui.spec.ts`、`tests/task-cockpit.spec.ts`

1. 编写失败测试：任务区/任务条 DTO 保留统计；格式化函数展示“第 N 轮”和活跃时长；驾驶舱有两种时长且零值历史任务正常呈现。
2. 运行 `pnpm vitest run tests/task-ui.spec.ts tests/task-cockpit.spec.ts -t "运行轮次|运行时长"`，确认缺少字段或展示。
3. 在远端摘要传递 `runtimeMetrics`；客户端新增中文时长格式化，列表/任务条展示轮次与活跃时长，驾驶舱展示活跃与自然经过时长和开放轮状态。
4. 重跑聚焦测试并确认通过。
5. 提交：`feat: show task runtime metrics`。
