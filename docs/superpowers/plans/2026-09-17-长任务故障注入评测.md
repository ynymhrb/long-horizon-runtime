# 长任务故障注入评测实施计划

> **供代理执行者使用：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐项执行本计划。步骤使用复选框（`- [ ]`）跟踪。

**目标：** 建立 35 个确定性回归场景加 30 个本机模型真实任务的故障注入评测体系，并生成可审计的恢复、幂等性、token 和最终正确性指标。

**架构：** 在现有 scenario/evidence/metrics 体系之上增加显式启动的 `validation/live` 层。评测适配器装饰 planner 与 execution 边界，按 durable 工作流步骤注入故障并写 trace；真实运行驱动器只接收已验证的本机 DSH 命令向量，使用一次性临时 profile。确定性 fixture 使用同一 contract 和报告逻辑验证，不依赖模型。

**技术栈：** Node.js ESM、JavaScript JSDoc、TypeScript、Vitest、DSH subagent provider、YAML、JSON evidence bundle。

**设计规范：** `docs/superpowers/specs/2026-09-17-长任务故障注入评测设计.md`

## 全局约束

- 只修改 `D:\code\long-horizon-runtime`；不修改 DeepSeek Harness 源码或用户 profile 配置。
- 真实评测只由显式 CLI 启动，使用唯一临时工作区和临时 profile；安装、激活和 `pnpm test` 不得启动模型。
- 所有场景必须是 `read_only`；禁止网络、第三方写入与 `external_effect`。检测到外部副作用立即 hard stop。
- “步骤”是 durable DAG 中已开始的 execution attempt，不把模型内部不可观测的思考或工具调用冒充为步骤。
- 受控副作用只限临时工作区内带稳定幂等键的产物提交；缺少模型、token、trace、正确性或对照证据时必须为 `inconclusive`。
- 所有新增行为先写 focused Vitest 失败测试、亲自确认失败，再写最小实现。
- 文档、场景标题、CLI 摘要和面向用户错误消息使用中文；内部 JSON 字段维持既有 snake_case 约定。

- [ ] **Step 3: 实现最小装饰器和账本**

```ts
export function traceExecutionAdapter(inner: ExecutionAdapter, plan: FaultPlan, writer: EvaluationTraceWriter): ExecutionAdapter {
  let durableStep = 0
  return { async execute(input) {
    const step = ++durableStep
    writer.append({ phase: "attempt_started", durableStep: step, attemptId: input.attemptId })
    if (plan.decide({ durableStep: step, phase: "after_start", logicalActionKey: logicalActionKey(input) }) === "crash") throw injectedFailure("crash_after_step", step)
    return recordSettled(inner.execute(input), writer, step)
  } }
}
```

在 scheduler 写入 `ArtifactProduced` 前记录受控评测账本；重复键写入 `EvaluationDuplicateEffectDetected`，阻止第二次产物提交。

- [ ] **Step 3: 实现按模型环境分区的安全聚合**

```js
export function aggregateLiveMetrics(runs) {
  const complete = runs.filter(run => run.evidenceComplete)
  return {
    task_success_rate: rate(complete.filter(run => run.taskSuccess).length, complete.length),
    recovery_success_rate: rate(complete.filter(run => run.hasFault && run.recovered).length, complete.filter(run => run.hasFault).length),
    duplicate_side_effects: sum(complete.map(run => run.duplicateEffects)),
    average_retry_count: average(complete.map(run => run.retryCount)),
  }
}
```
