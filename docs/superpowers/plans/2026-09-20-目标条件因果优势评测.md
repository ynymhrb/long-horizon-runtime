# 目标条件因果优势评测实施计划

> **供代理执行者使用：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐项执行本计划。步骤使用复选框（`- [ ]`）跟踪。

**目标：** 在 Long Horizon Runtime 中建立可重复、可审计的目标条件因果优势评测系统，支持确定性反事实分支、四种决策方法、统计聚合、显式真实模型运行和面试证据输出。

**架构：** 新系统位于 `validation/decision-quality`，默认与生产运行时隔离。确定性 fixture 提供已知潜在结果，分支运行器提供可执行干预证据，统一 scorer 接口实现四种方法，指标层将行动排序质量与最终任务结果分开报告；真实模型层只由显式命令启动，并通过环境变量读取密钥。

**技术栈：** Node.js ESM、JavaScript JSDoc、TypeScript、Vitest、JSON、Markdown、现有 validation evidence 约定。

**规范：** `docs/superpowers/specs/2026-09-20-目标条件因果优势评测设计.md`

## 全局约束

- 只修改 `D:\code\long-horizon-runtime`；不修改 DeepSeek Harness 源码或用户 profile。
- 所有新增文档、CLI 摘要和面向用户错误使用中文。
- 生产路径不得默认加载实验模块；`pnpm test` 不得调用模型或网络。
- 真实实验必须使用唯一临时工作区、显式 token/墙钟预算和只读或临时工作区内幂等操作。
- API 密钥只允许从 `DEEPSEEK_API_KEY` 环境变量读取，不得写入命令参数、提示词、证据包、测试快照或仓库。
- 正确性在效用中是词典序第一优先级，成本不得抵消错误结果。
- 缺失关键证据的运行必须是 `inconclusive`，不得用零值填补。
- 先完成 12 任务试验和方差分析，再决定正式重复次数；1 亿 token 是硬上限。
- 保留当前工作树中与本计划无关的用户改动，不覆盖、不回滚、不混入提交。

## 评审重点

- 候选行动为空、重复或 ID 不稳定时，契约应一次列出所有错误并拒绝运行；Task 1 覆盖。
- 反事实分支写入初始快照或其他分支时，运行器必须硬停止并保留污染证据；Task 4 覆盖。
- 分支结果并列或缺失时，指标必须给出可解释的并列/不确定结果；Task 2 覆盖。
- 评分器输出非有限数、概率不归一或证据引用不存在时，统一接口必须拒绝；Task 3 覆盖。
- live 运行缺少预算、密钥或显式开关，以及证据中出现密钥时，命令必须安全失败；Task 6 覆盖。

- [ ] **Step 3：实现确定性指标**

```js
export function deriveCausalAdvantages(outcomes) {
  return outcomes.map(current => {
    const alternatives = outcomes.filter(row => row.actionId !== current.actionId)
    const bestAlternative = Math.max(...alternatives.map(row => row.utility))
    return { actionId: current.actionId, advantage: current.utility - bestAlternative }
  })
}
```

Kendall `tau-b` 必须处理并列；聚合返回分子、分母、比率和 95% 任务级 bootstrap 区间。空输入返回 `null` 区间，不返回 `NaN`。
